# Vestiarion v0.1.0-beta.6 — Invoice capture from Chrome, a security page, two people per new payee

The sixth beta of Vestiarion. A Chrome extension sends an invoice you are looking at to your workspace as a draft for
review. A public security page sets out how data moves through the product and where each boundary is. Developers can
try the API from Postman and find the MCP server in the MCP Registry. And the first payment to a new payee's address now
always rests on two different people, however the address came in.

This release covers 8 merged pull requests (#358 to #365) since
[v0.1.0-beta.5](https://github.com/duongnq2798/vestiarion/releases/tag/v0.1.0-beta.5). Each feature was reviewed by an
independent reviewer before merge, and every defect found was fixed with a test that failed first. Production is
deployed from `main` on every merge, so it may already run newer changes than this release lists.

## Highlights

- **Capture invoices from Chrome (#361).** Vestiarion Invoice Capture sends an invoice you select on a page, or a file
  you choose, to your workspace as a draft. You check the fields it read, with what is missing named, and send it; an
  owner or admin then adds it as a bill through the same step as any bill, or discards it.
  - The extension connects by signing in and allowing it, never with an API key. It can only create and read its own
    drafts: it never adds a bill, approves or pays. A connection lasts at most 90 days and ends when its member can no
    longer add bills; Settings lists connected extensions with Disconnect.
  - The captured text is kept until the draft is decided, 30 days at most.
  - Proven in production end to end, from connecting the extension to adding the captured draft as a bill. Submitted
    to the Chrome Web Store; until it is listed, it is loaded unpacked.
- **A security page for reviewers (#359).** [vestiarion.xyz/security](https://www.vestiarion.xyz/security) describes,
  as the code does it today, tenant isolation, encryption, who can approve what, connector tokens, webhook signing, the
  signed ledger, retention and deletion, how the model is used and the services that process data, and ends with what
  we do not claim. The repository has a security policy, [SECURITY.md](https://github.com/duongnq2798/vestiarion/blob/main/SECURITY.md).
- **Two people behind every new payee (#364).** The first payment to a payee at an address needs two different people
  behind it. Whoever creates a payee link now counts as having given the address the payee sends through it, read from
  the workspace's signed ledger. For an address sent on GitHub with `/payto`, or one no member can be named as having
  given, one member confirms it and a different one approves its first payment; approving never counts as confirming.
  "Who can act" and the overdue email leave out whoever cannot approve it, and the workspace's only approver may still
  pay it, which the ledger records.
- **Try the API from Postman, and the MCP server in the Registry (#360, #363).** Two Postman collections and an
  environment, generated from the API's own description: "Getting Started" goes from a key to a first answer in three
  reads; the reference has every operation. `server.json` describes the remote MCP server for the official MCP
  Registry, and the MCP page says which key to use.
- **Plain words (#365).** The site says what Vestiarion is: your AI agent for bills and payments, for small businesses.
- **Release notes (#358)** for v0.1.0-beta.5.
- **Fixes (#362, #359).** Connector consent says what the model provider does under its own API terms (new consent
  versions `2026-10-15`). On Arc mainnet the agent's spending limit always stands, even when a workspace's was missing.
  An API write's idempotency outcome is deleted after its 24 hours.

## Database

One new migration brings the total to 114 (`0001_init.sql` to `0121_invoice_capture.sql`; numbers 0091 to 0093, 0096
to 0098 and 0119 are unused):

| Migration | Adds |
| --- | --- |
| `0121_invoice_capture.sql` | Captured invoice drafts, the extension's connections and one-time codes, and the functions that create, claim and decide drafts |

It is additive and idempotent, and is applied in filename order by `npm run db:migrate`. Publishing a release never
runs migrations.

## Known limitations

- **Beta.** Screens, wording and features change often. The spending-limit and escrow contracts have not been audited.
- **Invoice capture** is loaded unpacked until the Chrome Web Store lists the extension.
- **Commissions.** When the payout's creator and the partner it pays are a workspace's only approvers, a payout the
  agent holds can be approved by neither.
- **QuickBooks Online** still connects to sandbox companies only, until Intuit's app assessment is complete.
