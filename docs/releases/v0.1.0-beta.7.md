# Vestiarion v0.1.0-beta.7 — Invoice Capture on the Chrome Web Store, and safer resends

The seventh beta of Vestiarion. Vestiarion Invoice Capture is on the Chrome Web Store, and the copy you install there
connects with no change on the deployment. When Circle never answered a payment's send, the agent now looks the send up
before it checks or decides anything, and a payment sent again to a new address needs two people behind that address,
like any first payment. The Pipedrive and Asana listings are ready to submit, and the README links a new demo and
product tour.

This release covers 8 merged pull requests (#366 to #374) since
[v0.1.0-beta.6](https://github.com/duongnq2798/vestiarion/releases/tag/v0.1.0-beta.6). Each change was reviewed by an
independent reviewer before merge, and every defect found was fixed with a test that failed first. Production is
deployed from `main` on every merge, so it may already run newer changes than this release lists.

## Highlights

- **Invoice Capture on the Chrome Web Store (#370, #374).** Install it with Add to Chrome from
  [its store page](https://chromewebstore.google.com/detail/vestiarion-invoice-captur/jfhjgbdbolhnneomgifdnjamoldlioan).
  The store gave it the ID `jfhjgbdbolhnneomgifdnjamoldlioan`, which Vestiarion now allows as soon as invoice capture
  is on, so the store's copy connects with no change to `CHROME_EXTENSION_IDS`. A zip to load unpacked stays in the
  [guide](https://www.vestiarion.xyz/docs/guides/invoice-capture#1-install-it) for where the store is not available;
  every downloaded copy has the one ID `pemkppoklecedoebjfgjlgfibbepikki`, set by a public key in its manifest. The
  landing page and the README have an Add to Chrome button.
- **Look for an unanswered send before anything else (#367, #368).** When Circle never answered a payment's send, the
  transfer may have gone through anyway. The agent now looks it up on Circle first, sending nothing: a transfer Circle
  has is recorded as paid, one not listed yet waits for the next cycle, and only a send Circle never took goes on to the
  checks. A payment sent again to an address that two different people do not stand behind is held as
  `counterparty.new_payee` for a person, and their Approve and pay looks the earlier send up first, so a transfer
  Circle took is recorded rather than sent twice. Each send now records the address it pays.
- **Lost batches and escrow releases reconciled in one cycle (#372).** Milestones released together in one transaction
  are all recorded paid in the cycle that finds the transaction. A release already sent from an escrow hold is recorded
  as paid, and the hold as released, whatever the contractor's address says now.
- **Ready for the Pipedrive Marketplace and the Asana App Directory (#371).** What to submit to each, field by field
  within their limits, with the scopes and why each is needed, the reviewers' path, a demo script, the listing images
  and the icons, is in [docs/distribution](https://github.com/duongnq2798/vestiarion/tree/main/docs/distribution). An
  install started in Pipedrive now leads to the connect page instead of an expired-link error.
- **A new demo and product tour (#374).** [The demo](https://youtu.be/-gMv3ipzDyA) (2:55) and
  [the full product tour](https://youtu.be/yfDxzibSYQc) (7:15), recorded on the live product on October 15, 2026. The
  README says what shipped this week (#369).
- **Release notes (#366)** for v0.1.0-beta.6.

0098 and 0119 are unused).

## Known limitations

- **Beta.** Screens, wording and features change often. The spending-limit and escrow contracts have not been audited.
- **Invoice capture** sends drafts only to a workspace where the person connecting it is an owner or admin.
- **Commissions.** When the payout's creator and the partner it pays are a workspace's only approvers, a payout the
  agent holds can be approved by neither.
- **QuickBooks Online** still connects to sandbox companies only, until Intuit's app assessment is complete.
- **Pipedrive and Asana** listings are prepared, not yet submitted.
