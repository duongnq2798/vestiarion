# Vestiarion v0.1.0-beta.1 — Public beta

The first tagged release of Vestiarion: an AI treasury agent that pays a small business's bills in USDC on Arc, inside
limits that code and, on Arc mainnet, a contract enforce, with every decision signed into a ledger anyone in the
workspace can verify.

It names what [www.vestiarion.xyz](https://www.vestiarion.xyz) runs as of the commit below: 323 merged pull requests
(#1 to #325) since the first commit on September 24, 2026. It is a beta: anyone can sign in and use it, on Arc testnet
and on Arc mainnet, and it still changes every day. Production is deployed from `main` on every merge, so it may
already run newer changes than this release lists.

## Highlights

- **An agent that decides when and whether to pay.** Each cycle it reads the whole book (payables, contractors,
  receivables, compliance, treasury) and proposes pay, schedule, hold, request info or flag as fraud, with its
  reasoning, choosing the day to pay around due dates and early-payment discounts (#80). Anthropic, OpenAI or
  DeepSeek proposes; with no model key a written rule-based policy decides, and its answer is recorded beside the
  model's.
- **Deterministic guardrails, then people, then a contract.** Duplicate, risk, payment-limit, three-way-match (#201),
  new-payee (#204), two-approval (#208) and spending-limit (#120) rules run as ordinary code after the model and before
  any money moves. On Arc the agent's daily and 7-day spending limit is enforced by a contract (#149) that only the
  owner's wallet can change or stop (#246).
- **A signed, hash-chained decision ledger.** Every decision, refusal and human action is an Ed25519-signed entry that
  covers the one before (#2 to #7), with key rotation (#67), one-click verification, offline-verifiable exports (#65)
  and signed webhooks (#35).
- **Shadow mode.** A business keeps paying its bills its own way while the agent decides each one; a person agrees or
  disagrees, only agreed payments settle on Arc testnet at the real amount, and what the business really paid is
  recorded beside each decision (#251, #253, #254, #256, #260, #297, #312).
- **Arc testnet and Arc mainnet.** Each workspace lives on one network (#207). Arc mainnet is open to anyone who signs
  in (#226): pay from the owner's own wallet (#235) or a passkey wallet (#236), with two approvals above 100 USDC from
  the start (#220). The first Arc mainnet payment through the spending-limit contract settled on October 7, 2026.
- **Your books and CRM.** Bills come in from Xero (#319) and QuickBooks Online (#321) for a person to review; payments
  made on Arc are booked back into Xero after an owner or admin approves each booking (#322); won deals and their
  customers come in from HubSpot (#323, #324).

## What is in this release

**Paying bills.** Bills typed in, imported from a bill list in its own columns, dates and currency (#299), read from a
PDF (#94), forwarded to a workspace email address (#184), or added through the API (#171); recurring payments (#124);
EURC invoices and USDC-to-EURC swaps (#85, #107); payouts to other chains through CCTP and Gateway (#89, #98); payee
history bought over x402 before a first payment (#131); an approvals inbox with a pause switch (#25); a 14-day payment
plan (#315); and where each payment is, from the agent's decision to the books (#316).

**Contractors and payees.** Milestones verified by a merged GitHub pull request or a person (#84, #186, #197), bounties
from a pull request comment (#196), milestone escrow (#105), several milestones in one transaction (#128), pay a
freelancer in one step (#111), payee links where a payee confirms their own address (#75) or creates a passkey wallet
(#215), public payment receipts (#102) and an email to the payee once paid (#161).

**Getting paid.** Pay links and money received matched to what was owed (#116), reminders (#165), payments applied to
several invoices or part of one, with fees and reversals kept apart (#317), and signed deals turned into collection
schedules (#318).

**Treasury and planning.** Safe to spend today (#119), a USYC reserve on Arc testnet with cash brought back for
payments (#123, #163), cash scenarios for clients paying late (#311), and USDC added to a workspace's wallet from
another chain (#272).

**Reports and evidence.** A workspace report of what the agent did with real bills (#292), compared with what the
business really paid, from a CSV or a bank statement (#297, #312), shared by a revocable link (#313); one evidence chain
per payment, from purchase order to receipt (#310); a new limit tried on past decisions before it is applied (#298); and
[Open numbers](https://www.vestiarion.xyz/open), read from production on every load (#69, #242).

**Workspaces and team.** Accounts, self-serve workspaces, four roles, invitations and sample data (#8, #17, #20, #62);
per-member notifications by email and Telegram (#30, #166, #177); Slack decisions and approvals (#175, #180); a
workspace frame with a command palette and grouped sidebar (#26, #303).

**For developers.** A REST API at `/api/v1` with per-member keys (#33, #171, #182), signed webhooks (#35), a remote MCP
server (#46), the TypeScript SDK [`@vestiarion/sdk`](https://www.npmjs.com/package/@vestiarion/sdk) (#176; 0.3.2 on npm,
versioned on its own line), and developer docs with an OpenAPI reference (#43). Changes to the API and webhooks are
listed for integrators in the [API changelog](https://www.vestiarion.xyz/docs/changelog).

## Safety

- Row-level security under a dedicated tenant role, behind a per-workspace data access layer (#12, #15).
- A stop switch every deployment obeys, checked addresses, no reject over an unknown transfer, and screening that
  fails closed (#205, #206); payments to a counterparty never screened are held (#151).
- Payment integrity: one claim per decision, approver counts enforced, the ledger chain checked on insert, and an
  agent resend under two approvals (#214); a payment approved in shadow mode goes to the address the card showed
  (#252).
- A member's API keys end with their membership (#174); pay-link tokens are redacted before page views reach
  analytics (#291).

## Database

This release contains 100 migrations, `0001_init.sql` to `0106_accounting_postings.sql` (numbers 0091 to 0093 and 0096
to 0098 are unused). They are idempotent and applied in filename order by `npm run db:migrate`; publishing a release
never runs them. A self-hosted deployment applies all of them before running this release.

## Known limitations

- **Beta.** Screens, wording and features change often. The spending-limit and escrow contracts were written for
  Vestiarion and have not been audited.
- **Arc mainnet is USDC on Arc only.** EURC, the USYC reserve, milestone escrow, CCTP and Gateway payouts, x402 and
  shadow mode are Arc testnet only, and features Arc mainnet lacks are not shown there. Slack can approve payments on
  Arc testnet only; chats never approve Arc mainnet payments, and Telegram never approves or pays.
- **USYC is permissioned.** The live reserve needs Circle to allowlist a workspace's operating and reserve wallets;
  until then the reserve stays simulated.
- **QuickBooks Online** connects with development keys and sandbox companies. Production companies need Intuit's app
  assessment, which is pending. QuickBooks is read-only: payments are booked back into Xero only.
- **Xero** writes nothing until a person approves each booking, and a payment on Arc testnet or in shadow mode is
  booked only into a Xero demo company.
- **HubSpot** is read-only and polled every 15 minutes. Its app has not yet been verified by HubSpot, so HubSpot may
  say so when a person connects it.
- **Usage.** The Arc mainnet path is proven with the team's own workspace; [Open numbers](https://www.vestiarion.xyz/open)
  shows current customer counts on each network.
