# Vestiarion v0.1.0-beta.3 — Currencies, first tasks and walkthroughs

The third beta of Vestiarion. Small businesses outside the US can now run their books in their own currency, and every
figure says where its rate came from. Each member starts with a first task built for their role. Evidence links are
checked before they count. The Xero and HubSpot guides open with walkthrough videos recorded in the live product.

This release covers 5 merged pull requests (#339 to #343) since
[v0.1.0-beta.2](https://github.com/duongnq2798/vestiarion/releases/tag/v0.1.0-beta.2), released the same day. Each
feature was reviewed by an independent reviewer before merge, and every defect found was fixed with a test that failed
first. Production is deployed from `main` on every merge, so it may already run newer changes than this release lists.

## Highlights

- **Work in your own currency (#342).** Every amount keeps four things separately: the figure and currency written on
  the bill, the workspace's reporting currency, the rate used (with who published it and when), and what moves on Arc.
  - An owner or admin sets a **Reporting currency**: USD, EUR, SGD, JPY, KRW, PHP or MYR.
  - The report's **Currencies and rates** shows each figure in its own currency, then in the reporting currency with
    the rates used. A rate that was not recorded shows as unknown and is never guessed.
  - A bill paid after the rate moved shows its **FX variance**.
  - Cash scenarios take a rate for each currency and are saved as versions that never change.
  - USDC is counted against US dollars only at its 1:1 redemption peg, and always says so. Yen and won have no
    decimals anywhere.
  - Rates are recorded every hour by a scheduled job. A page shows the newest rate with its age and never waits on the
    rate feed.
- **A first task for each role (#341).** Each member gets a short checklist built for their role. A step is ticked
  because it happened in the workspace, and no step offers anything the role cannot do.
  - Owners and admins: add a first bill, see the agent's decision, set the limits.
  - Approvers: read why a bill is held, then decide it.
  - Accountants: book a payment or apply a receipt, then download the month's hand-off.
  - An accepted invitation lands on the role's first step.
- **Evidence links people can actually open (#341).** A pull request or link is checked before it counts as verified.
  One that can't be opened is named with the reason and never offered.
  - Vestiarion contacts only GitHub's API and its own file storage. It never opens any other site from its server.
  - A private repository visible only to the deployment reads exactly like a deleted one, so nothing about it leaks.
- **Walkthrough videos in the Xero and HubSpot guides (#343).** Each guide opens with a film of under two minutes,
  recorded in the live product on Arc testnet with demo data. The videos are served from Vestiarion's own site, with
  no embed and no cookies, and come with a transcript. The HubSpot film follows one deal from Closed Won in HubSpot to a
  20 USDC deposit paid on Arc, matched by the agent 3 seconds later, and written back to the HubSpot deal.
- **The standalone primitives repository (#340).** The README links
  [duongnq2798/vestiarion-primitives](https://github.com/duongnq2798/vestiarion-primitives). It holds the spending-limit
  and escrow contracts byte for byte, a Foundry build that reproduces the Arc mainnet bytecode, unit, fuzz and invariant
  tests, deploy scripts and viem examples.

## Database

Two new migrations bring the total to 108 (`0001_init.sql` to `0114_onboarding_marks.sql`; numbers 0091 to 0093 and
0096 to 0098 are unused):

| Migration | Adds |
| --- | --- |
| `0113_currency_provenance.sql` | Reporting currencies, recorded rates, FX variances and scenario versions |
| `0114_onboarding_marks.sql` | The marks behind each member's first-task checklist |

Both are additive and idempotent, and are applied in filename order by `npm run db:migrate`. The hourly rates job is a
Supabase Cron line in `supabase/cron/watches.sql` (`vestiarion-fx-rates`), run once by hand. Publishing a release never
runs migrations.

## Known limitations

- **Beta.** Screens, wording and features change often. The spending-limit and escrow contracts have not been audited.
- **Arc mainnet is USDC on Arc only**, as in earlier betas. Payments settle in USDC (or EURC on Arc testnet) whatever
  the bill's currency; reporting in other currencies is for reading and planning.
- **Rates.** A workspace that starts using a new currency gets its first recorded rate at the next hourly run. Rates
  from Xero and QuickBooks are not read yet. A payment made before the first recorded rate shows its variance as
  unknown.
- **Evidence checks** share the deployment's GitHub API limit with merge verification.
- **QuickBooks Online** still connects to sandbox companies only, until Intuit's app assessment is complete.
