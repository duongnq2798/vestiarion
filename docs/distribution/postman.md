# Publishing the Postman collections

The collections are generated by `npm run postman:build` (`scripts/lib/postman.ts`) from the OpenAPI document, committed
under `public/postman/`, and served by the site:

- `https://www.vestiarion.xyz/postman/vestiarion-getting-started.postman_collection.json`
- `https://www.vestiarion.xyz/postman/vestiarion-api-reference.postman_collection.json`
- `https://www.vestiarion.xyz/postman/vestiarion.postman_environment.json`

`tests/postman.test.ts` fails while they differ from the document, or hold anything shaped like a key. The user guide is
[Use Vestiarion from Postman](https://www.vestiarion.xyz/docs/get-started/postman). Putting them in a public Postman
workspace is a person's task, done once, then repeated when the API changes.

## Checklist

- [ ] The PR adding the files is merged and deployed: each URL above answers `200` with JSON.
- [ ] Sign in to Postman with the team's account, not a personal one, and give the team a public profile (team
      settings) if it has none. A public workspace needs one.
- [ ] Create a workspace named **Vestiarion API**, visibility **Public**, with the summary: "The Vestiarion REST API:
      read a workspace's ledger, books and the agent's decisions; add counterparties, invoices and milestones."
- [ ] **Import** each of the three URLs (paste the link). Import the Getting Started collection first, so it is listed
      first.
- [ ] Before publishing, open the **Vestiarion** environment and check `apiKey`: its type is secret and its initial
      value is empty. Never paste a key into this workspace's copy, not even as a current value: send test requests
      from a private copy instead.
- [ ] In each collection's overview, check the description renders and links the guide.
- [ ] Optional: add the workspace to the Postman API Network, if Postman offers it for the team's public workspace,
      with the category Finance.
- [ ] Optional: from the Getting Started collection, choose **Share**, then **Run in Postman**, and send the button's
      Markdown to whoever maintains the docs, to add to the guide's first section.
- [ ] Post the workspace's link where developers look: the guide (in a docs PR), the README's Developers row, X.

## When the API changes

A PR that changes an operation, a parameter, an example or an error runs `npm run postman:build` and commits the
result, as the test requires. Once it is deployed, update the public workspace:

- [ ] In the public workspace, **Import** the changed collection's URL again and choose **Replace**. Postman recognizes
      it by its fixed `_postman_id`, so forks and the Run in Postman button keep pointing at it.
- [ ] Open one changed request and check it matches its reference page.
